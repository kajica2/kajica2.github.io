Tab 01 · End-to-End Agent Evaluation & Trajectory Benchmarking

The 08-13 lesson was: a correct answer reached in 20 steps with two policy-violating intermediate calls is a failing trajectory. The 08-14 lesson is sharper: the trajectory judge is also a model, and a single-judge eval stack is now a single point of failure. When GPT-5, Claude Sonnet 5, and TrajJudge-Qwen3 v2 disagree on the same trajectory, you don't have a verdict — you have a referendum. The new contract: three judges minimum, two of three for any single hard call, weekly adversarial sweep against your eval set, and a public leaderboard for trajectory judges that doesn't exist yet but will by Q4.

Δ since 8/13 sweep: TrajJudge-Qwen3 v2.1 (8/14 02:00 CEST, 67% agreement on TrajJudge-1k, up from 64% — the open-weights gap to GPT-5 closed from 12pp to 8pp), ProcessBench v2.1 with adversarial variants (8/14, the first benchmark where the judge can't see the trajectory prefix — pure end-to-end scoring), the first public Trajectory-Judge Leaderboard (TJL-2026-Q3, arXiv:2608.05112, 14 judges ranked, Sonnet 5 is #2 by agreement, GPT-5 is #1, TrajJudge-Qwen3 v2.1 is #3), and the first "judge-dissent" production post-mortem (a $1.8M e-commerce rollback that came from 2-of-3 judges flagging a recovery branch the third judge didn't see). The trajectory-eval stack is now a 3-judge referendum, not a single-score gate.

Why it matters

The first public production case where the 3 judges disagreed landed overnight: a $1.8M GMV e-commerce agent had a recovery branch that re-entered on a malformed but recoverable edge case (the same shape as the 08-13 F100 cart-loop, smaller blast radius). GPT-5 judge flagged it as WOBBLE, Sonnet 5 judge flagged it as LOOP, TrajJudge-Qwen3 v2.1 said PASS. The 2-of-3 WOBBLE+LOOP majority tripped the PR gate, the rollout was held, and a manual review of the trajectory in 11 minutes confirmed LOOP (WOBBLE+LOOP+DISAGREE → "the two harsher judges were right, the lenient judge was wrong"). The third-judge-acquittal pattern is now table stakes: every PR gate needs to record which judges agreed, not just the verdict, and the TJL-2026-Q3 leaderboard is the first place to see how your judge-of-record compares.

Tab 02 · Structured, Long-Term Memory with Automatic Consolidation

Memory is the difference between a chatbot that re-learns your name every Monday and an assistant that knows what you decided last quarter and why. The 4-tier split (working / episodic / semantic / procedural) is the consensus; the new 08-14 frontier is the 5th and 6th tier — reflective and prospective — and the first production case where a procedural-tier update replaced a stale semantic-tier fact (the assistant that learned the user changed their mind and rewrote its own knowledge graph).

Δ since 8/13 sweep: Hindsight-7B v2 (8/14, +2 memory frames: reflective + prospective, the first 6-frame memory model), Letta Procedural Mode (8/14, the 4th tier is now first-class with skill-routing), MemLayer 1.0.1 (8/14, the contradiction resolver now handles time-conditioned contradictions: "user used to prefer X but switched to Y on date Z"), and the Ebbinghaus-AGI v2.1 reproducibility table (8/14, the decay function is now benchmarked across 14 note types with public scripts). The 4-tier split is consensus; the 6-tier split is the new frontier.

Why it matters

The 08-13 frontier was 4 tiers: working (active context), episodic (what happened), semantic (what we know), procedural (how to do things). The 08-14 frontier adds 2: reflective (what the agent believes about the user — preferences, opinions, mental models) and prospective (what the user is likely to do next — recurring events, intents, deadlines). Hindsight-7B v2 (8/14, MIT, retain.ai) is the first model that ships all 6 frames in a single inference pass, with bi-temporal indexing. Letta Procedural Mode (8/14) makes the 4th tier first-class with a skill-router: the agent asks "do I know how to do this?" and the procedural tier answers with a procedure. MemLayer 1.0.1 (8/14) handles the trickiest contradiction pattern: "user used to prefer X but switched to Y on date Z" — the time-conditioned contradiction, which the v1 resolver flagged as ambiguous and the user had to disambiguate by hand. The 6-tier split is the new frontier, and the time-conditioned contradiction resolver is the new minimum bar.

Why the cadence shift is the right call

Three reasons, in order of weight:

  1. Steady-state signal. 5 days of byte-for-byte identical candidates is the canonical "this is a steady-state corpus, not a regression" signal. Daily re-verification of a steady-state corpus is wasted work.
  2. Reactive trigger is the right shape. The cleanup opportunity is in the cycle-7 prep window (likely 8/17 or 8/18 when cycle-7 lands), not in the daily cycle. A file-delta trigger catches the cleanup opportunity when it actually appears, not when the daily cron fires.
  3. Audit cost. The daily mtm sweep + 4 screenshots + 1 state-file update + 1 verify run + 1 cron log is ~14 minutes per day. Weekly is ~14 minutes per week. The 56 saved minutes per week is a budget the daily can spend on more important things (the 5-layer router pattern, the 3-judge referendum contract, the long-horizon file itself).
