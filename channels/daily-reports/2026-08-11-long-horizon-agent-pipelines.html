Tab 01 · End-to-End Agent Evaluation & Trajectory Benchmarking

Final-answer scoring marks a failing agent green. The answer was right. The path was wrong — 20 steps, two policy violations, an exfiltration. Trajectory eval closes that gap.

Δ since 8/10 sweep: rStar2-Agent trajectory diagnostics, ACE step-level rubric scoring, AEQS (AgentEval Quality Survey) 31-dim framework, and Future AGI's gateway-embedded evals. The field is consolidating around six sub-scores per trajectory, not one.

Why it matters

A correct answer reached in 20 steps with two policy-violating intermediate calls is a failing trajectory. Production agents need four layers: unit, trajectory, outcome, online. Anything less accumulates technical debt in the form of undetected regressions.

Tab 02 · Structured, Long-Term Memory with Automatic Consolidation

A context window is short-term and re-paid every turn. Memory is persistent, has its own storage tier, evolution rules, and a forgetting policy. The two are complements, not substitutes.

Δ since 8/10 sweep: MemMachine (private KG, new from Mem0 team Aug 4), Hindsight (bi-temporal recall with negation), the A-MEM agentic memory note-type taxonomy, and ACON (allocator-consolidator separated loop).

Why it matters

LongMemEval showed 1M-token models drop 30%+ accuracy when forced to recall across sessions without a memory layer. The dream is hybrid: structured graph for relations, vector store for surface recall, the agent itself paging between them — and a sleep-time process that consolidates the way the hippocampus does.

Prompts that work

# 1) Single-pass ADD-only extraction (Mem0 v3 idiom) — one LLM call, no UPDATE/DELETE
extract_prompt = """
Read this conversation turn. Emit only NEW facts about the user
that are not already in the existing memory store. Skip generic chit-chat.
Skip things the user already corrected this turn.
Each fact: { "subject": str, "predicate": str, "object": str, "confidence": 0-1, "ts": ISO8601 }
Existing memory (for dedup awareness): {existing}
Conversation: {turn}
"""

# 2) Conflict resolution — when new info contradicts old, stamp the old invalid, keep history
conflict_prompt = """
New fact: {new_fact}
Candidate conflicting edges: {candidates}
Decide:
  REPLACE — new supersedes (mark old invalid_at=now, add new with valid_at=now)
  COEXIST — both can be true (e.g., user has two roles over time)
  KEEP_BOTH — no real conflict (different entities, scope, or time window)
Return JSON: { "verdict": str, "rationale": str, "patch": [...] }
"""

# 3) A-MEM note-type classifier — 5-way, drives consolidation behavior
classify_prompt = """
Classify this fact into exactly one note type:
  FACT       — verifiable claim about the world
  PREFERENCE — user's taste/opinion/bias
  EVENT      — time-bounded occurrence
  SKILL      — capability the user has or wants
  RELATION   — entity-to-entity connection
Fact: {fact}
Return JSON: { "type": str, "confidence": 0-1, "tags": [str] }
"""

# 4) Sleep-time consolidation — the dreaming prompt
dream_prompt = """
You are consolidating a user's memory graph overnight.
Inputs:
  - 1,247 facts from the last 30 days
  - existing long-term graph (512 nodes)
Tasks:
  1. Merge facts that say the same thing (different wording).
  2. Drop facts contradicted by a more recent fact (mark prior invalid_at).
  3. Promote repeated patterns to long-term preferences.
  4. Demote single-occurrence chit-chat to ephemeral.
  5. Surface 3 surprising connections the user might have forgotten.
Output a diff. Do not rewrite the entire graph.
"""

Tab 03 · Agent-First Observability, Guardrails & Real-Time Interruption

An agent that can send emails, modify databases, and make purchases needs a stop button that understands intent. Keyword filters are not it.

Δ since 8/10 sweep: Nvidia NeMo Guardrails 2.0 (colang 2.0 with state machines), Agent Jailbreak Eval (AgentBreach) — 47 new attack patterns documented, Datadog LLM Observability (Aug 2026), and PagerDuty's interrupt policy engine for long-running agent loops.

Why it matters

Enterprises won't deploy agents that can autonomously send emails, modify databases, or make purchases without strong guardrails. Current guardrails are either too blunt (keyword filters) or only applied at the final output. The shift: policy as code, evaluated mid-loop, attached to spans, intercepting at semantic moments.

Tab 04 · Tool Integration & Dynamic API Orchestration

The hard part of tool integration isn't the API call. It's the auth, the rate limits, the schema drift, the PII redaction, the cache, the retry, and the prompt that tells the model when NOT to use it.

Δ since 8/10 sweep: MCP 1.2 (the spec finally stabilized, with resumability + sampling), ToolUniverse (200+ pre-built MCP servers from academic consortium), MCP security incidents (the August 6 2026 supply-chain attack on a popular MCP server), and Stripe Agent Toolkit (payment-native tools).

Why it matters

Connecting agents to real APIs is still messy. Developers manually write function descriptions, struggle with auth, and discover edge cases late. A "tool factory" that turns any API into a safe, agent-optimized tool with built-in rate-limiting, caching, and credential rotation would accelerate adoption. MCP is winning because it's open and stable. The remaining work is safety and supply chain.

Tab 05 · Self-Improving Agent Pipelines (Automated Fine-Tuning from Experience)

The agent that doesn't get better is a calculator. The agent that does is a colleague. The difference is a closed loop: failures → training data → fine-tune → benchmark → canary → ship.

Δ since 8/10 sweep: rStar2-Agent (Microsoft, July 2026) with self-evolving trajectory synthesis, ACE (Agentic Context Engineering) — three papers in one month on context-as-parameter, agentEvol (open-source self-evolution loop), and the first production Online DPO deployment case study (Klarna, partial).

Why it matters

Human-labeled data is expensive, and static prompt engineering plateaus. Teams want agents that get better from production use, learning from both successes and human corrections. The new framing: context as a parameter. You don't always need a weight update — sometimes evolving the prompt + few-shots + memory is faster, safer, and easier to roll back.

Tab 06 · Multi-Agent Collaboration & Debate Pipelines with Provenance

One agent in a loop is brittle. Two agents arguing is expensive. Three agents in a structured debate with provenance is a system you can audit and defend.

Δ since 8/10 sweep: GAVEL (NeurIPS 2026) — formal consensus with provable optimality, AFlow (AFlow-Agent, July 2026) — agentic workflow evolution, the debate-as-modular-debate pattern from MASLab, and the Minority Sentinel pattern (a watchdog agent that flags the loudest agent's blind spots).

Why it matters

Complex enterprise tasks (legal contract review, financial analysis, engineering design) need multiple perspectives and a transparent chain-of-reasoning. Simple "round-robin" agent chats fail to provide reliability guarantees. The shift: structured role-based collaboration, shared blackboard state, formal consensus, provenance that survives serialization.

sentinel_prompt = """

"""

consensus_prompt = """
Each agent: {agent_outputs}

Return: { "decision": str, "confidence": 0-1, "dissent": [...], "provenance": [...] }
"""

Tab 07 · Privacy-Preserving Agent Pipelines for Personal Data

The most useful agents (personal assistants, health advisors) need intimate data. Privacy regulations and user trust demand that sensitive data stay under the user's control. Local-first is the only design that scales trust.

Δ since 8/10 sweep: Apple Private Cloud Compute (PCC) v2 with verified telemetry, TEE-OS (Aug 2026) — open-source confidential-compute agent runtime, AgenTEE now production on Arm CCA, and the EU AI Act enforcement deadline (Aug 2 2026) — all deployed agents in EU now need data-residency proof.

Why it matters

It's technically hard to split reasoning between local and cloud models dynamically, to identify what information is safe to send, and to maintain a useful memory graph while keeping raw content encrypted. The new wave: verified confidential compute, on-device memory, encrypted retrieval, and provable data residency.

The benchmark that matters most

It's not the one in the paper. It's the one in your production: CPSO — cost per successful outcome. Not tokens. Not traces. Successful outcomes — generated, sent, accepted by the business without rework. That single number tells you whether every other optimization is real or theater.

Second-most-important: T2R — time to recovery when something goes wrong. An agent system without observability has T2R measured in days. With Phoenix + Langfuse + PagerDuty interrupt, T2R is measured in minutes. The difference between a system you can ship and a system you have to babysit.

Eight pipelines. One report. The cheap ones — cost routing and agent eval — fund the expensive ones — memory, debate, confidential compute. Ship the cheap ones first. They pay for the rest. And every system you ship needs CPSO and T2R measured before it needs any other optimization.
