Tab 01 · End-to-End Agent Evaluation & Trajectory Benchmarking

Final-answer scoring marks a failing agent green. The answer was right. The path was wrong — 20 steps, two policy violations, an exfiltration. Trajectory eval closes that gap.

Why it matters

A correct answer reached in 20 steps with two policy-violating intermediate calls is a failing trajectory. Production agents need four layers: unit, trajectory, outcome, online. Anything less accumulates technical debt in the form of undetected regressions.

Tab 02 · Structured, Long-Term Memory with Automatic Consolidation

A context window is short-term and re-paid every turn. Memory is persistent, has its own storage tier, evolution rules, and a forgetting policy. The two are complements, not substitutes.

Why it matters

LongMemEval showed 1M-token models drop 30%+ accuracy when forced to recall across sessions without a memory layer. The dream is hybrid: structured graph for relations, vector store for surface recall, the agent itself paging between them — and a sleep-time process that consolidates the way the hippocampus does.

that are not already in the existing memory store. Skip generic chit-chat.

# 2) Conflict resolution — when new info contradicts old, stamp the old invalid, keep history
conflict_prompt = """
New fact: {new_fact}

Decide:
  REPLACE — new supersedes (mark old invalid_at=now, add new with valid_at=now)
  COEXIST — both can be true (e.g., user has two roles over time)
  REJECT — new is hallucinated; ignore
Return JSON with decision, reason, and updated edges.
"""

# 3) Sleep-time reflection (Anthropic Dreaming / Letta sleep-time agent idiom)
reflect = """
Recent episodic trace (last 24h): {episodes}
Long-term store: {store}
Produce 0–5 NEW high-order insights that:
  (a) cross multiple episodes,
  (b) are not yet in the store,
  (c) are at a higher abstraction than the events themselves.
Do not summarize. Do not repeat. Output JSON array of insights.
"""

# 4) Recency-decay reranking (production default)
final_score = 0.7 * relevance + 0.3 * exp(-lambda * days_since)
#  lambda ≈ ln(2) / 14d → 14-day half-life, tune from production retrieval

Tab 03 · Agent Observability, Guardrails, and Real-Time Interruption

Tracing tells you what happened. Eval tells you if it was good. Guardrails stop the bad from reaching the user — at sub-200ms, with graduated interventions, ideally before the tool call.

Why it matters

Agents autonomously call tools, send email, write rows. Enterprises won't deploy them without runtime enforcement. A keyword filter is too blunt. A post-hoc audit is too late. The new floor: streaming interception, intent modeling, and policy-as-code with hardware-rooted attestation behind it.

Tab 04 · Tool Integration & Dynamic API Orchestration

Function calling is a runtime convention inside one LLM API. MCP is a transport-level protocol that lives outside it. In 2026 you ship one MCP server and every compatible client can use it. That's the unlock.

Why it matters

Connecting agents to real APIs is still messy. The 2026-07-28 MCP spec — stateless core, MRTR, async tasks, formal extension system — pushed the protocol from a developer-facing tool-calling convention toward enterprise-grade production infrastructure. Auto-generation from OpenAPI collapsed the onboarding tax.

Tab 05 · Self-Improving Agent Pipelines (Auto Fine-Tuning from Experience)

Human labels are expensive. Static prompts plateau. The agent should learn from production — failure → preference pair → DPO → canary → ship or roll back, all without a human in the loop.

Why it matters

Production agents accumulate failure modes faster than anyone can label them. The 2026 stack: SFT for instruction following, DPO/SimPO for general preferences, GRPO/DAPO with verifiable rewards for reasoning. The closed loop: capture failures → synthesize preference pairs → fine-tune a smaller model → canary it → beat the old one on cost and quality, or revert.

Prompts that work

# 1) Best-of-N task prompt — rejection sampling for DPO pairs
bos_prompt = """
You are attempting: {task}.
Run the test suite when done. Return:
  status: "pass" | "fail"
  diff:   unified diff of your changes
  notes:  one-paragraph rationale
Do not explain before attempting. Just attempt.
"""

# 2) DPO preference pair generator — deterministic judge (no LLM cost)
def to_pair(trace, test_runner):
    won  = next((t for t in trace.attempts if test_runner(t) == "pass"), None)
    lost = next((t for t in trace.attempts if test_runner(t) == "fail"), None)
    if won and lost:
        return {"prompt": trace.prompt, "chosen": won.code, "rejected": lost.code}
    return None

# 3) Automatic curriculum (Voyager-style — what skill to learn next?)
curriculum = """

Open unexplored territory in: {domain}
Propose the next 3 skills to acquire. Each skill: name, description (1 sentence), why now.
Do not duplicate. Do not propose skills already in the library.
"""

# 4) Self-verifier (Voyager iterative prompting)
verify = """
The skill output was: {output}
Environment state: {state}
Did the skill achieve its stated goal? Reply:
  VERIFIED — clear evidence in state
  REJECTED — no evidence, here's why
  AMBIGUOUS — partial; what to check next
"""

Tab 06 · Multi-Agent Collaboration & Debate with Provenance

Three models agreed. It was still wrong. An ICML 2025 study found that when two models both err, they converge on the same wrong answer 60% of the time. The fix isn't more votes — it's structured debate with provenance.

Why it matters

Cross-model agreement is correlated evidence, not confirmation. Models share training data, architectures, post-training recipes. The 2026 audit: agreement-to-correctness Spearman ρ of 0.20–0.59 — positive but weak. The most agreement-prone model had the least trustworthy agreement signal. Real reconciliation is a designed process, not a vote count.

Tab 07 · Privacy-Preserving Local-First Agents

The most useful agents need intimate data. The most intimate data is the one you can't send to a third party. Local-first isn't a preference in 2026 — it's a regulatory and trust floor.

Why it matters

Tab 08 · Cost-Optimisation & Inference Routing for Agent Loops

Frontier models cost 20–100× more than their small-model cousins. The cheapest way to cut an AI bill without cutting capability is to stop paying frontier prices for easy requests.

Why it matters

40–70% of production queries can be served by the cheap model with no detectable quality loss. 20–30% require frontier. The middle 10–20% benefits from cascade verification. The 2026 stack: semantic cache → difficulty router → cheap → escalate on confidence → cost attribution per step → drift monitor. Done right, you keep 95% of frontier quality at 15–30% of the bill.

End-to-end pipeline demo

query → semantic cache (cosine > 0.92) hit-rate ~40% → else RouteLLM classifier (difficulty) → nano tier (Haiku 4.5 / GPT-5.4 nano) at $0.05–$0.30/M → conformal confidence check → if low confidence → Sonnet 4 / GPT-5 mid ($0.50–$3/M) → if still low → Opus 4 / o3 frontier ($3–$15/M) → PII redact result → cost attribution per agent step → weekly re-routing audit (drift check)

Prompts that work

# 1) Difficulty classifier (the cheap-LLM-as-router)
classify = """
Read this user query and rate its difficulty on 3 axes (0=trivial, 10=hard):
  reasoning      — multi-step logic required?
  tool_count     — how many distinct tools will the agent need?
  context_depth  — needs deep retrieval / long doc reasoning?
Reply JSON: {"reasoning": int, "tool_count": int, "context_depth": int, "tier": "nano|mid|frontier"}
Query: {query}
"""

# 2) Conformal threshold setter (distribution-free, no calibration drift)
def conformal_threshold(scores, alpha=0.1):
    # 90% of cheap-model outputs that score above this are actually correct
    return np.quantile(scores, 1 - alpha)

# 3) Cascade trigger (cheaper than re-querying)
trigger = cheap_response if confidence(conformal, cheap.score) > tau else escalate(cheap, mid)
