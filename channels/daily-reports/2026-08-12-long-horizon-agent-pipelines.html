Tab 01 · End-to-End Agent Evaluation & Trajectory Benchmarking

Final-answer scoring marks a failing agent green. The answer was right. The path was wrong — 20 steps, two policy violations, an exfiltration. Trajectory eval closes that gap.

Δ since 8/11 sweep: EvalSync 0.4 (the schema-drift-aware parser that absorbs a new eval-runner format per release), TrajJudge-Qwen3 (a 32B open-weights judge that matches GPT-4o on the rStar2-AgentBench split), and the Inspector Pro mode in Phoenix 4.1 (per-tool-call replay with eval-overlay diffing). The trajectory-eval stack is now table-stakes for any agent that ships to production.

Why it matters

A correct answer reached in 20 steps with two policy-violating intermediate calls is a failing trajectory. Production agents need four layers: unit, trajectory, outcome, online. Anything less accumulates technical debt in the form of undetected regressions. The 08-11 cycle-7 escape case (a 0-card silent regression rescued by the parser's h3-fallback) is the same shape: a green verify on the wrong unit of measurement.

Tab 02 · Structured, Long-Term Memory with Automatic Consolidation

A context window is short-term and re-paid every turn. Memory is persistent, has its own storage tier, evolution rules, and a forgetting policy. The two are complements, not substitutes.

Δ since 8/11 sweep: MemMachine 0.3 (the on-prem KG gained a public REST adapter), Hindsight-1.1 (bi-temporal recall with negation + temporal-range queries), the Forgetting Curve pattern from Ebbinghaus-AGI (a paper that frames forgetting as a tunable hyperparameter), and MemLayer (a new startup with a $14M seed that wraps the same primitives behind a managed API).

Why it matters

LongMemEval showed 1M-token models drop 30%+ accuracy when forced to recall across sessions without a memory layer. The dream is hybrid: structured graph for relations, vector store for surface recall, the agent itself paging between them — and a sleep-time process that consolidates the way the hippocampus does. The new framing: forgetting is a feature, not a bug, and the policy is yours, not the model's.

Prompts that work

# 1) Single-pass ADD-only extraction (Mem0 v3 idiom) — one LLM call, no UPDATE/DELETE
extract_prompt = """
Read this conversation turn. Emit only NEW facts about the user
that are not already in the existing memory store. Skip generic chit-chat.
Skip things the user already corrected this turn.
Each fact: { "subject": str, "predicate": str, "object": str, "confidence": 0-1, "ts": ISO8601 }
Existing memory (for dedup awareness): {existing}
Conversation: {turn}
"""

# 2) Conflict resolution — when new info contradicts old, stamp the old invalid, keep history
conflict_prompt = """
New fact: {new_fact}
Candidate conflicting edges: {candidates}
Decide:
  REPLACE — new supersedes (mark old invalid_at=now, add new with valid_at=now)
  COEXIST — both can be true (e.g., user has two roles over time)
  KEEP_BOTH — no real conflict (different entities, scope, or time window)
Return JSON: { "verdict": str, "rationale": str, "patch": [...] }
"""

# 3) Ebbinghaus-AGI forgetting curve — half_life per note-type
half_life = {
  "FACT":       90,    # days — verifiable world facts decay slowly
  "PREFERENCE": 180,   # taste evolves slowly, half-life is long
  "EVENT":      30,    # time-bounded, half-life matches the event's window
  "SKILL":      365,   # skills are durable
  "RELATION":   120,   # relationships shift, but not quickly
}
# retrieval weight = base_similarity * exp(-elapsed_days / half_life)
# below threshold (e.g., weight < 0.05) → cold-storage or drop

# 4) Sleep-time consolidation — the dreaming prompt
dream_prompt = """
You are consolidating a user's memory graph overnight.
Inputs:
  - 1,247 facts from the last 30 days
  - existing long-term graph (512 nodes)
  - Ebbinghaus decay weights (facts below 0.05 already pruned)
Tasks:
  1. Merge facts that say the same thing (different wording).
  2. Drop facts contradicted by a more recent fact (mark prior invalid_at).
  3. Promote repeated patterns to long-term preferences.
  4. Demote single-occurrence chit-chat to ephemeral.
  5. Surface 3 surprising connections the user might have forgotten.
Output a diff. Do not rewrite the entire graph.
"""

Tab 03 · Agent-First Observability, Guardrails & Real-Time Interruption

An agent that can send emails, modify databases, and make purchases needs a stop button that understands intent. Keyword filters are not it.

Δ since 8/11 sweep: NeMo Guardrails 2.1 (colang 2.0 with span-attached interrupts), the first published mid-loop PII-leak incident report from a Fortune 500 finance team (Aug 9 2026), and PagerDuty Interrupt Engine GA (was beta on 8/11). The "guardrail as final-output filter" framing is now a documented anti-pattern in three production post-mortems.

Why it matters

Enterprises won't deploy agents that can autonomously send emails, modify databases, or make purchases without strong guardrails. Current guardrails are either too blunt (keyword filters) or only applied at the final output. The shift: policy as code, evaluated mid-loop, attached to spans, intercepting at semantic moments. The 08-09 finance post-mortem showed a $0.002 PII-leak that cost $4.2M in audit/remediation — the policy was final-output only, the leak was mid-loop.

Tab 04 · Tool Integration & Dynamic API Orchestration

The hard part of tool integration isn't the API call. It's the auth, the rate limits, the schema drift, the PII redaction, the cache, the retry, and the prompt that tells the model when NOT to use it.

Δ since 8/11 sweep: MCP Registry 1.0 (the post-Aug 6 incident answer — signed MCP server metadata, mandatory provenance, automatic audit), ToolSandbox 0.4 (capability tokens now support per-tool-cost ceilings), and the first academic study of MCP-server selection accuracy (SIGCOMM 2026 workshop). Stripe Agent Toolkit GA'd with PCI-scope-reduction built-in.

Why it matters

Connecting agents to real APIs is still messy. Developers manually write function descriptions, struggle with auth, and discover edge cases late. A "tool factory" that turns any API into a safe, agent-optimized tool with built-in rate-limiting, caching, and credential rotation would accelerate adoption. MCP is winning because it's open and stable. The remaining work is safety and supply chain. The MCP Registry 1.0 is the post-incident answer to "how do we trust a third-party MCP server?"

Tab 05 · Self-Improving Agent Pipelines (Automated Fine-Tuning from Experience)

The agent that doesn't get better is a calculator. The agent that does is a colleague. The difference is a closed loop: failures → training data → fine-tune → benchmark → canary → ship.

Δ since 8/11 sweep: The Klarna rollback post-mortem (public, Aug 11 2026) — the most detailed self-improving-agent case study to date, with hard numbers on what went wrong, what worked, and the eval-suite gap that bit them. Plus: rStar2-Agent v1.1 with the self-evolving-trajectory release, and a new "context-only" path (ACE 2.0) that closes 92% of the weight-update gap at 4% of the cost.

Why it matters

Human-labeled data is expensive, and static prompt engineering plateaus. Teams want agents that get better from production use, learning from both successes and human corrections. The new framing: context as a parameter. You don't always need a weight update — sometimes evolving the prompt + few-shots + memory is faster, safer, and easier to roll back. The Klarna case proves it: weight updates with an incomplete eval suite is a customer-tone time bomb.

# 2) Spend tracker — daily / monthly budget enforcement
class SpendTracker:
  def __init__(self, daily_budget=5.00, monthly_budget=150.00):
    self.daily = daily_budget
    self.monthly = monthly_budget
  def can_spend(self, est_cost):
    return self.daily_spent() + est_cost <= self.daily \
       and self.monthly_spent() + est_cost <= self.monthly
  def degradation(self, est_cost):
    # if cost_ceiling blown, downgrade to smaller model, NOT retry bigger
    if not self.can_spend(est_cost):
      return {"action": "downgrade", "from": est_cost, "to": "haiku-or-smaller"}
    return {"action": "proceed"}
